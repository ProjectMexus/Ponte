# 用戶版服務工作區設計

## 目標

將目前把後端原始資料直接攤開的服務工作區，改成以辦事為中心的摘要介面。使用者仍然看得到預約進度、服務名稱、日期／時間、地點和下一步操作，但不再看到 API 工具名稱、請求編號、資源類型、內部 ID、部門 ID 或英文欄位。

## 核准方向

採用「使用者版摘要工作區」：保留流程可見性，但以用戶語言呈現；不新增「查看技術詳情」入口，也不把最後結果以外的流程資料全部刪掉。

## 資訊架構

右側工作區分成三層：

1. **流程進度**：保留目前工作流的步驟，但使用簡短的用戶語言，顯示已完成、目前進行或需要處理。
2. **目前資料**：只顯示和辦事有關的摘要。
   - 服務：服務名稱、所需時間、地點。
   - 可選時段：日期、開始／結束時間、地點。
   - 已選時段／預約完成：服務名稱、日期、時間、地點、完成狀態；若後端提供必要提醒，也可顯示提醒。
3. **操作區**：只保留選擇服務、選擇時段、確認預約、取消或轉交人工等下一步操作。

地點是主要資訊，必須保留。前端使用友善名稱映射，例如 `LOC-IMAGING-CENTER` 顯示為「影像中心」、`LOC-REHAB-01` 顯示為「復康治療室」；未知地點顯示「服務地點」，不可直接把 `LOC-*` 代碼展示給使用者。

## 前端資料呈現

在 `frontend/interaction-view.js` 增加以業務語意為主的資料轉換，而不是修改 middleware 或醫療 API contract。

- 服務選擇按鈕顯示「服務名稱｜分鐘數｜地點」。
- 時段選擇按鈕顯示本地化日期、時間範圍和地點。
- 確認和完成畫面使用一張簡潔摘要卡，不顯示 `resourceType`、`id`、`service_id`、`slot_id`、`department_id`、`location_id`、英文名稱、容量、剩餘名額或後端來源欄位。
- 只有完成操作所必需的轉介／關聯門診資料，才在確認畫面以正常表單欄位保留。
- 日期時間使用現有 `zh-HK` 格式化能力；顯示格式應易讀，避免 ISO 字串。
- 其他服務（現金分享、長者活動）沿用摘要渲染邏輯，只挑選有用欄位；無法辨識的原始欄位不顯示，不輸出整包 JSON。

工具執行事件仍由 middleware 回傳，但不再由前端渲染 `tool_events` 卡片或請求編號。這只改變展示層，不影響重試、錯誤處理或 API 呼叫。

## 流程進度

將後端步驟 ID 映射為用戶語言，例如：

| 內部步驟 | 使用者顯示 |
| --- | --- |
| `load_appointments` | 確認現有預約 |
| `load_services` / `select_service` | 選擇服務 |
| `search_slots` | 查找可預約時段 |
| `select_slot` | 選擇時段 |
| `confirm_appointment` | 確認預約 |
| `create_appointment` | 提交預約 |
| `get_task_status` | 完成預約 |

前端需根據 `step.status` 或後端既有的 `ok` 值推導狀態：`ok: true` 為已完成、`ok: false` 為需要處理；當前步驟優先顯示為目前進行，其餘尚未執行步驟顯示尚未開始。沒有可辨識步驟時使用簡短的「服務步驟」作為最後後備文字，但不顯示工具名稱或 ID。

## 介面清理

- 移除標示「測試模式」的徽章。
- 連線狀態只保留「服務已連線」或「服務中心未連線」，移除工具能力數量。
- 移除輸入框下方的 MCP 測試指令提示。
- 保留語音輸入、停止朗讀、人工協助、錯誤提示和重要操作確認。
- 保留「每一步都看得見」的產品承諾，但實際步驟內容改為用戶語言。

## 錯誤與相容性

- middleware 錯誤仍顯示現有可理解的錯誤訊息，不顯示 request ID 或底層工具名稱。
- 空服務、空時段、無預約等狀態維持清晰的空狀態提示。
- 不改變 `sendMessage`、`sendAction`、確認預約、取消、重試或語音流程。
- 保持大字、高對比、鍵盤 focus 與手機版單欄佈局。

## 變更範圍

- `frontend/index.html`：移除面向開發測試的文案與徽章，保留必要的語音、輸入和工作區 landmark。
- `frontend/interaction-view.js`：新增業務摘要渲染、地點名稱映射、步驟文案和步驟狀態推導；停止渲染 tool events。
- `frontend/styles.css`：移除不再使用的 tool event 視覺規則，調整摘要卡與操作區的視覺層級。
- `tests/test_frontend_static.py`：更新前端 contract，覆蓋友善欄位、地點映射、內部欄位不顯示及診斷文案已移除。
- `frontend/README.md`：更新使用者可見功能描述，說明工作區顯示摘要而非原始 backend JSON。

不修改 middleware、MCP registry、mock backend、資料格式或既有業務流程。

## 驗證與完成條件

1. `python3 -m unittest tests.test_frontend_static -v` 通過。
2. 執行所有既有 Python 測試，確認 API 與工作流沒有回歸。
3. `node --check` 檢查所有前端 JavaScript 模組。
4. 本地 smoke check：醫療預約流程中只看到服務、日期／時間、地點、進度和操作；看不到工具名稱、請求編號或內部 ID。
5. 空資料、錯誤回應、取消、確認和手機版仍可理解且可操作。

完成條件是：一般使用者不需要理解 MCP、FHIR 或內部資料模型，也能看懂目前進度、選擇服務／時段並完成預約。
